2. 연결 문자열 복사
========================================
[ ] 상단 Connect 버튼 -> Session pooler 탭 (포트 5432)
[ ] 반드시 "복사 아이콘"으로 복사할 것

  ** 주의 1 - 드래그 복사 금지
     입력칸이 가로로 잘려 있어 사용자명의 .<ref> 부분이 잘려 나간다.
     2026-07-17에 이걸로 배포가 두 번 실패했다.
     에러가 "password authentication failed"로 나와서
     비밀번호 문제로 착각하기 쉽다.

  ** 주의 2 - Direct connection 쓰지 말 것
     db.<ref>.supabase.co 형태는 IPv6 전용이라 연결이 안 된다.
     반드시 pooler 주소(aws-1-ap-northeast-2.pooler.supabase.com)를 쓴다.

  올바른 형태:
  postgresql://postgres.<ref>:<비밀번호>@aws-1-ap-northeast-2.pooler.supabase.com:5432/postgres
                       ^^^^^^ 이 점과 ref가 반드시 있어야 한다

3. Render 환경변수 교체
========================================
[ ] Render 대시보드 -> work-calendar 서비스 -> Environment
[ ] DATABASE_URL 을 2번에서 복사한 새 문자열로 교체

    (안 뜨면 Manual Deploy -> Deploy latest commit)

  * 관리자 계정은 새 DB의 users 가 비어 있으므로
    CAL_ADMIN_USER / CAL_ADMIN_PASS 값으로 다시 만들어진다.
    Render 에 이미 들어있는 값 그대로 쓰면 된다.

4. 배포 성공 확인 (제일 중요)
========================================
[ ] Render -> Events 탭에서 "Deploy live" 인지 확인

  ** 사이트가 열린다고 배포 성공이 아니다.
     Render 는 새 배포가 실패하면 옛 인스턴스를 계속 서빙한다.
     반드시 Events 탭을 먼저 볼 것.

  실패 코드 읽는 법:
     Exited with status 3  -> DB 연결 실패 (DATABASE_URL 확인)
     Exited with status 1  -> 필수 환경변수 누락 (3번 목록 확인)

  로그에 뜨는 사용자명으로 원인 구분:
     "for user postgres"          -> .<ref> 가 빠졌다 (2번 주의 1)
     "postgres.<ref> not found"   -> 프로젝트가 없거나 정지됨
